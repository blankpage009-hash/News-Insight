## 새로 찾은 것
**N-1. 구글 계정 '연결'을 통한 관리자 탈취 가능성** — server.js:181–185 `isGoogleUser` (직접 줄 확인함)
- 상황 : Supabase 에서 이메일 가입이 켜져 있고 "이메일 확인"이 꺼져 있고, 같은 이메일 계정 자동 연결이 켜진 경우. 공격자가 관리자 이메일로 비밀번호 가입 → 진짜 관리자가 구글로 로그인해 계정이 합쳐짐 → `providers` 에 google 이 들어감 → 공격자가 비밀번호로 로그인해도 관리자로 인정.
- 서버는 "계정에 구글이 연결돼 있나"만 보고 "이번 로그인이 구글인가"는 안 봄.
- 분류 보안 · 위험도 중(조건부) · 로컬 검증 **N** → 이번엔 **보고만**.
- **2026-10-15 Supabase 대시보드 확인 (사용자 스크린샷, Authentication > Sign In / Providers)** : Email 공급자 ENABLED · "Confirm email" **ON** · "Allow manual linking" OFF · "Allow anonymous sign-ins" OFF.
  → 공격 전제 중 "이메일 확인이 꺼져 있음"이 **성립하지 않는다.** 공격자는 관리자 메일함이 없어 확인 메일을 못 눌러 로그인 자체가 안 되고, 서버(184줄)도 `email_confirmed_at` 이 없으면 통과시키지 않는다. → **위험도 중 → 하(방어 겹침)로 낮춤.**
  → 남는 선택 사항 : 이 앱은 구글 로그인만 쓰므로 Email 공급자를 DISABLED 로 끄면 이 경로가 아예 사라진다(사용자 결정, 코드 수정 아님). 이메일 로그인을 쓰는 시험 계정이 없는지 확인 후.
